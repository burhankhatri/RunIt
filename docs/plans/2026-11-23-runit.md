# RunIt implementation plan

**Goal:** ship the app in `docs/specs/2026-11-23-runit-design.md`.
**Architecture:** Rust core, C ABI, two native shells, llama.cpp child processes.

Each task is test first, then code, then a conventional commit.

1. Core: `gguf` read (truncated headers too) and write. Tests: round trip, cut header, array values.
2. Core: `hardware` and `engine` device parsing. Tests: captured Metal, Vulkan and CPU output.
3. Core: `predict` least squares, memory tiers, offload. Tests: recover known constants; tiers.
4. Core: `bench` orchestration. Test: live engine run, opt in by `RUNIT_ENGINE_DIR`.
5. Core: `catalog` distil, search, plan. Tests: real captured fixtures.
6. Core: `quality` matching. Tests: aliases match, fine-tunes do not.
7. Core: `recommend`. Tests: thresholds, dedupe, unrated exclusion.
8. Core: `download` resume, checksum, cancel, retry. Tests: local HTTP server.
9. Core: `run` measure and chat. Tests: SSE parsing, live opt in.
10. `runit-cli`, `runit-ffi`. Test: FFI smoke from Rust; CLI end to end.
11. Accuracy harness: predicted against measured on real models. Record in `docs/accuracy.md`.
12. macOS app. Verify by driving and screenshotting it.
13. Windows app. Verify on a Windows runner with screenshots.
14. `install.sh`, `install.ps1`, CI and release workflows. Verify by installing from the release.
